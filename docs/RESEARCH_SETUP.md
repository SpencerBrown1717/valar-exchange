# Daily Research · owner setup

Research is part of this VALAR repository. Content is stored durably in `src/research-data.json`; publication slots, deduplication and withdrawal tombstones are stored privately in `content/research/state.json`. The existing Vercel Git deployment prerenders the index and article routes. No database, new app, public publishing endpoint, newsletter or visitor API-key form is needed.

## Current status: generation paused

The workflow is installed for approximately **17:23 UTC daily** and supports a private manual draft run. No job can start until the owner sets `VALAR_RESEARCH_APPROVED=true`; no scheduled publication runs until `VALAR_RESEARCH_DAILY_ENABLED=true`. `content/research/config.json` also starts with `enabled:false`. No inference has been sent, no fixture news published and no credentials created/configured.

Activation requirements are separate from the working public Research pages:

1. Resolve the existing GitHub Actions account-payment/spending-limit failure. This repository's hosted jobs previously failed before any steps. No billing or limit change is made by this implementation.
2. Qualify the exact intended Qwen model and approve its blog-serving allowance. The inspected Mini gateway documents nonstream `/v1/chat/completions` with `model`, `messages`, `stream:false`, `max_tokens`, `temperature`; only `qwen3:8b` was found locally. Do not assume a higher-quality preset or silently substitute a paid model.
3. Establish an owner-approved authenticated HTTPS Tahoe API origin reachable from the GitHub-hosted runner. The inspected Mini gateway binds `127.0.0.1:3001`, which a remote runner cannot reach. Do not expose that service, install a runner/tunnel, change Tailscale or repurpose the direct gateway secret without separately approved setup. Prefer a dedicated Tahoe caller key with the approved allowance through the established API admission/metering path.
4. In this repository's **Settings → Secrets and variables → Actions**, enter `TAHOE_RESEARCH_API_KEY` as a secret using GitHub's secure UI. Never paste it into chat or a file. Set variables `TAHOE_RESEARCH_CHAT_URL` to the approved full HTTPS `/v1/chat/completions` endpoint, and `TAHOE_RESEARCH_MODEL` to the qualified exact Qwen tag. The adapter uses the documented text-chat contract only. These server-side values never enter the frontend/build.
5. For a private first draft only, after the above owner decisions, commit `enabled:true` in `content/research/config.json` and set `VALAR_RESEARCH_APPROVED=true`. The publishing job uses the ephemeral repository-scoped `GITHUB_TOKEN` with `contents:write`; no persistent GitHub credential is needed. Repository/organization restrictions may refuse this permission or the normal main update: honor them, do not change/bypass protections. The workflow runs site checks itself because bot-token pushes do not start another push workflow.
6. Run **Daily VALAR Research** manually from Actions. Manual runs always hold the checked draft in the private `valar-research-review` artifact (14-day retention), never publish it. Download and review the article, provenance and economic/status language. If there is no substantive news, the artifact remains unchanged content (empty before the first news article); this is a skip, not a first-article validation. After approving a real draft, commit its exact `src/research-data.json` and `content/research/state.json` files through normal repository review. Verify Vercel Ready at that commit and the unauthenticated public article. Only then set `VALAR_RESEARCH_DAILY_ENABLED=true` to enable hands-off daily publication. A subsequent bot commit triggering the existing private-repository Vercel integration remains unproven until an authorized live scheduled run. GitHub schedules can be delayed or skipped; this is not an exact-time delivery guarantee.

No provider purchase, account permission change, serving request, runner installation or live activation occurs merely by merging this feature. Until the setup is completed, the public page shows an honest empty industry-coverage state and preserves the original evergreen guides.

## Owner controls

- **Pause immediately:** disable `Daily VALAR Research` in GitHub Actions, unset `VALAR_RESEARCH_DAILY_ENABLED`, or unset `VALAR_RESEARCH_APPROVED`. For a durable in-flight publication guard, run `npm run research:pause`, commit the config change and deploy. A main change rejects an older in-flight proposal. Disabling a schedule alone does not retroactively undo a running job.
- **Edit:** copy an article object to a local JSON file, edit its text, then `npm run research:edit -- SLUG FILE`. Identity/source/publication date are preserved; updated time is recorded. Review and commit normally. The generator never overwrites existing articles.
- **Remove:** `npm run research:remove -- SLUG`, then review and commit. The article disappears from the next deployed build; the private daily/story ledger remains so a retry cannot republish it. Git history and third-party caches are not erased.
- **Failure state:** the workflow's failed step/annotation identifies the held stage. No raw provider body, key, evidence packet or secret is logged. A timeout retries once after 20 seconds; otherwise the day remains unpublished. After repair, manually rerun from latest main. Existing published content remains usable.
- **Rollback:** revert content/code through normal repository review. Never erase the ledger merely to rerun a day. Keep the existing Vercel project/domain.

Local verification: `npm run check`. Fixtures remain in tests only. `npm run research:generate` is paused by default and is not a local inference test shortcut. See [the versioned editorial playbook](RESEARCH_PLAYBOOK.md).
