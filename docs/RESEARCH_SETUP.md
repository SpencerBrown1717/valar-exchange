# Daily Research · owner setup

Research is part of this VALAR repository. Content is stored durably in `src/research-data.json`; publication slots, deduplication and withdrawal tombstones are stored privately in `content/research/state.json`. The existing Vercel Git deployment prerenders the index and article routes. No database, new app, public publishing endpoint or visitor API-key form is needed. Newsletter delivery remains a separate workflow.

## Owner controls

- **Pause immediately:** disable `Daily VALAR Research` in GitHub Actions, unset `VALAR_RESEARCH_DAILY_ENABLED`, or unset `VALAR_RESEARCH_APPROVED`. For a durable in-flight publication guard, run `npm run research:pause`, commit the config change and deploy. A main change rejects an older in-flight proposal. Disabling a schedule alone does not retroactively undo a running job.
- **Edit:** copy an article object to a local JSON file, edit its text, then `npm run research:edit -- SLUG FILE`. Identity/source/publication date are preserved; updated time is recorded. Review and commit normally. The generator never overwrites existing articles.
- **Remove:** `npm run research:remove -- SLUG`, then review and commit. The article disappears from the next deployed build; the private daily/story ledger remains so a retry cannot republish it. Git history and third-party caches are not erased.
- **Failure state:** the workflow's failed step/annotation identifies the held stage. No raw provider body, key, evidence packet or secret is logged. Inference timeouts and other serving failures are not automatically retried; they may already have consumed allowance. The day remains unpublished. Reconcile uncertain usage with Tahoe before a new attempt, then manually run from latest main after repair. Existing published content remains usable.
- **Rollback:** revert content/code through normal repository review. Never erase the ledger merely to rerun a day. Keep the existing Vercel project/domain.

Local verification: `npm run check`. Fixtures remain in tests only. `npm run research:generate` remains paused by default. `npm run research:draft` runs the same authorized live editorial flow privately; it still requires the dedicated server-side configuration and never reserves a publishable proposal.
